A harness is the coding-agent program that runs a session. fno supplies workflows and hooks for supported harnesses.

Start with the [quickstart](/quickstart). For worker creation, see [run a fleet](/guides/run-a-fleet).

## Workflow prompts

| Harness | Target prompt | Where to type it |
| --- | --- | --- |
| Claude Code | `/fno:target` followed by the task | Claude Code prompt |
| Codex CLI | `$fno:target` followed by the task | Codex prompt |
| OpenCode | `/fno:target` followed by the task | OpenCode prompt |

These forms select a workflow. They are not shell commands and do not select the model.

Use the same harness prefix for `fno:think`, `fno:blueprint`, `fno:review`, `fno:ship`, and `fno:fix`.

Other harnesses can have different hook and skill support. Check the installed integration before assuming the same lifecycle behavior.

## Launch axes

| Axis | Meaning | How it is selected |
| --- | --- | --- |
| Harness | Program running the agent | `-H` on a worker launch |
| Provider | Vendor serving the model | Provider routing and account configuration |
| Model | Model answering the prompt | Harness model selection |
| Effort | Reasoning setting | Harness effort selection |
| Account | Credentials used for access | Registered account selection |

A Codex harness does not make a shortened session ID safe to address. For mail, use its exact registered name or full ID.

## Execution lanes

| Lane | Interaction | Typical use |
| --- | --- | --- |
| `thread` | Persistent, attachable | A worker that continues across turns |
| `pane` | Interactive mux pane | A worker you want to watch in a fixed layout |
| `headless` | Noninteractive | One exchange with a final result; `--once` requests this lifecycle |
| `cloud` | Remote execution | A configured remote worker substrate |

Availability depends on the installed harness and configured services. A refused lane is not an instruction to bypass its gate.

## Check integration readiness

Use the setup dry run to inspect detected harnesses without applying changes:

```bash
fno config setup run --dry-run --json
```

The JSON includes detected harnesses and proposed setup actions. Read those actions before running an interactive setup or applying configuration.
