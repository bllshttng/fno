A target is a task with a finish line. fno connects the task to a plan, an owner, and evidence of completion.

To try it first, follow the [quickstart](/quickstart). To assign work, use [the fleet guide](/guides/run-a-fleet).

## Follow one task

1. You ask for a small change in a repository.
2. A backlog node records that work. A node is a task record with a stable ID and a readable slug.
3. A plan records scope, files, acceptance criteria, and verification steps.
4. A live claim identifies the session that owns the task.
5. The agent edits an isolated Git worktree and opens a PR.
6. Completion checks read the PR, CI, and configured review requirements.

The ID, slug, branch, session, and PR identify different things. A worker can tell you the corresponding values for its task.

## The parts

| Part | What it records | What it does not prove |
| --- | --- | --- |
| Node | Requested work and its relationships | That an agent is working now |
| Plan | Scope and acceptance criteria | That implementation passed verification |
| Claim | Current work ownership | That the work is complete |
| Session | One agent's work and transcript | That its output was merged |
| Worktree | An isolated checkout and branch | A security sandbox |
| PR | Proposed changes and review evidence | That every check passed |

## Worktrees isolate edits

A worktree lets two tasks use separate branches and files. It does not isolate credentials, network access, or processes.

The canonical checkout is the project's main checkout. A feature worktree is another checkout attached to the same Git repository.

Run plans you trust. Read the intended scope before granting an agent permission to execute it.

## Dependencies and parallel work

A node can depend on another node. That relationship keeps dependent work from starting before its prerequisite is ready.

Independent tasks can run together. Shared files, machine capacity, provider limits, and configured policies can restrict that concurrency.

Do not start a second worker on a task merely because its first worker is quiet. Check its claim and transcript first.

[Manage a backlog](/guides/manage-backlog#respect-ownership) shows the claim command and how to record a prerequisite.
