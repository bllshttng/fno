Run one target in a repository you can push to. Your result is a PR whose checks and review you can inspect.

## Before you begin

You need Git, curl, GitHub CLI (`gh`), and Claude Code or Codex CLI. Authenticate GitHub CLI and your coding harness first.

Use a small existing repository with a GitHub remote and passing checks. Choose a task you understand and can review.

## 1. Install

Run this in a terminal:

```bash
curl -fsSL fno.sh | sh
```

The installer provisions the CLI and wires supported harnesses it detects. It installs uv if needed and may update your shell profile.

Open a new terminal, then check the CLI:

```bash
fno --version
```

The command prints `fno` followed by a version. An isolated installation during verification printed `fno 0.4.4`.

If the command is missing, follow [installation checks](/install#check-your-installation). For another harness, use the [harness reference](/reference/harnesses).

## 2. Open your project

Open Claude Code or Codex in the repository you chose. Start a new harness session after installation so it discovers the plugin.

Confirm that the harness exposes the `fno:target` skill. If it does not, follow [plugin troubleshooting](/troubleshooting#the-harness-cannot-find-fnotarget).

> **Warning:** A target can edit files, run commands, use paid model credentials, and push a branch. Read the task first.

## 3. Give the agent one small target

In Claude Code, enter this prompt:

```text
/fno:target "Add a short repository overview to README.md, using only facts from this repository."
```

In Codex, use this prompt instead:

```text
$fno:target "Add a short repository overview to README.md, using only facts from this repository."
```

These are harness prompts, not terminal commands. Use one of them for this task.

Target creates an isolated worktree, plans the change, implements it, and reviews the diff. It pushes a branch and opens a PR.

The agent reports a PR URL. Its wording and generated README text vary. Open that URL to inspect the actual change.

## 4. Read the result

Check the PR diff, its current checks, and its review findings. A PR URL alone proves neither green checks nor completed review.

Your configuration controls review requirements and automatic merging. Check that policy before the run. See [configuration](/reference/configuration#automatic-merging).

By default, automatic merging is disabled. An enabled policy can merge the PR after its gates pass.

You have taken one small task through implementation to a PR. [How completion works](/concepts/completion) explains the evidence behind each state.

## Clean up

Close an unwanted practice PR through GitHub. Keep any branch or worktree that contains changes you need.

Do not delete the worktree while an agent is still using it. Merged worktrees follow the project's cleanup policy.
