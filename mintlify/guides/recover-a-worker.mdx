---
title: "Recover a worker"
description: "Inspect a quiet session before you resume or stop it."
---

A quiet worker can be waiting for CI, review, provider capacity, or input. Inspect it before launching a replacement.

## Before you begin

Install fno through the [quickstart](/quickstart). Use a practice worker from [the fleet guide](/guides/run-a-fleet), or a session you own.

You need its exact name or full session ID. The [CLI reference](/reference/cli#session-recovery) lists the recovery commands.

## Inspect first

```bash
fno agents session list
```

Find the session. Check its liveness and latest progress. Then use `fno agents session peek` with that name to read recent transcript records.

If the transcript names a pending check or refusal, address that cause. Starting another worker does not remove it.

## Resume a stopped session

Use `fno agents session resume` with the exact session name. Resume tries to preserve the existing work and session context.

If the command cannot recover the session or its account, it refuses. Read the refusal and its suggested hand-run recovery.

Do not delete the worktree or overwrite its files to make recovery proceed. Preserve unfinished changes before considering a replacement.

## Stop a worker

After reading the result, use `fno agents session stop` with the practice worker's name to stop it.

Stopping a process is not proof that its task completed. If the work is unfinished, preserve its branch and worktree.

Do not stop other live workers while testing these instructions. The examples here concern sessions you created or explicitly own.

## Further recovery

Keep the exact refusal, session ID, worktree path, and last transcript event. Include those facts in a request for help.
