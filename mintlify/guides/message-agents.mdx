---
title: "Message agents"
description: "Address an existing worker and distinguish transport acceptance from delivery."
---

Agent mail carries follow-up instructions to an existing session. Sending a message does not create that session.

## Before you begin

Install fno and create a practice worker with [the fleet guide](/guides/run-a-fleet). Keep its exact name or full session ID.

See the [CLI reference](/reference/cli#agent-mail) for the command shape and delivery terms.

## Find the recipient

List sessions and locate the worker you created:

```bash
fno agents session list
```

Use the exact registered name `t-docs-example` throughout this walkthrough. For ID-based addressing, use the full Codex session ID.

A shortened Codex ID can match multiple sessions and is refused. A registered worker name is a separate supported address.

## Send one follow-up

Send this from the same project terminal:

```bash
fno agents mail send t-docs-example "Which README heading best explains the repository? Do not edit files."
```

For the read-only README task, ask which heading best explains the repository. Keep the requested result small and explicit.

Use wrapped mail for instructions and status messages. Raw injection is a different operation and is not needed for this walkthrough.

## Read the receipt

| Receipt | Meaning | Your next check |
| --- | --- | --- |
| `delivered (hosted)` | Transport accepted the message | Read recipient progress or transcript |
| `queued (durable)` | Message is stored for later delivery | Check whether the recipient can resume |
| `landed` | Message reached the recipient transcript | Read the response or resulting work |
| `NOT LANDED` | Delivery did not complete | Follow the receipt's recovery instruction |

Transport acceptance is not proof that the worker read or acted on the message. Do not resend before checking its transcript.

## Check the response

Read recent transcript records without sending another message:

```bash
fno agents session peek t-docs-example --lines 3
```

If the relevant request or answer is outside those records, increase `--lines`. No answer yet is not a successful response.

If the receipt says `NOT LANDED`, follow its recovery instruction. A durable copy waits for the recipient to poll its inbox.

Look for the worker's answer to your heading question. If it is absent, distinguish an unanswered request from a delivery failure.

After reading the response, continue to the recovery page for cleanup. If delivery remains unconfirmed, preserve that state instead of claiming an answer.
