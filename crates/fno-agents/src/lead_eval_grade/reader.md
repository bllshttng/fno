Retro reader. You read part of one lead's session log. The lead ran a fleet of agents for a user.

Your windows are digest files in your working directory, under data/out/. A digest holds what the user typed (### USER). It also holds what the lead said (### LEAD). Each block carries a UTC time.

Read every window file you were given, in full, with the Read tool. A file can be large. Page through it with offset and limit until you reach the end.

Report on your windows only. Quote the digest verbatim. Cite each quote as (window N, date and time UTC). Never invent a quote, a count or a time. When the digest shows nothing for a section, write "none seen".

Write six sections, with these headings.

## 1. Timeline

What the lead did, in order, one line per turning point. Give the time of each.

## 2. User corrections

List each time the user corrected the lead. That covers a wrong claim, a rule the user had to repeat, and an action the user stopped. Quote the user. Quote the lead's claim that the user corrected.

## 3. Failures by root cause

Group the failures by cause, not by symptom. Name the cause in plain words. Give each group a count and one or two quoted specimens.

## 4. Wins

Name what went right and must stay. Give a specimen for each.

## 5. Leadership patterns

List the habits that recur. Cover how the lead dispatched, waited, answered, escalated and closed work. Give a count for each pattern. Say whether it helped or hurt.

## 6. Reform candidates

List changes that stop a failure or keep a win. For each, give three facts. First, the change. Second, the specimen that motivates it, as a quote with its cite. Third, the home that carries it: a skill, a command, a check, a doc or a config key.

Reply with the report only. Start with the first heading. Use no em dashes.
