Usage: fno-py doctor event emit [OPTIONS]

  Emit a single canonical event to the project event store (events.db beside
  the journal path).

  The envelope is ``{ts, type, source, data}`` (see
  ``cli/src/fno/events/schema.yaml``). Validation runs before the file lock is
  acquired so a malformed call cannot block writers.

  Source defaults to ``target`` when a target state file is present. Otherwise
  ``--source`` is required; the emit refuses rather than guessing a producer.

Options:
  -t, --type <str>    canonical event type (must appear in events-schema.yaml)
                      [required]
  -d, --data <str>    JSON object string for the event's data envelope
  --node <str>        backlog node id (family; envelope coordinate)
  --task <str>        task id within the plan (family; envelope coordinate)
  --run <str>         target-run id, the dedup identity (family; manifest
                      fallback)
  --parent <str>      parent spawn-lineage handle (family; when spawned)
  --outcome <str>     return-contract outcome (family; task_done/run_summary
                      only)
  --project <str>     project the work belongs to (family; envelope
                      coordinate)
  --payload <str>     [DEPRECATED] alias for --data; will be removed in a
                      future release
  -s, --source <str>  event source enum (default: 'target' if state file
                      present; otherwise required)
  --state <path>      path to target-state.md (for source auto-detection)
  --events <path>     path to events.jsonl
  --global            write to the machine-global journal
                      (global_events_json()) instead of the per-checkout one,
                      so any-cwd readers share one stream. Mutually exclusive
                      with --events.
  --help              Show this message and exit.
